# 8bit随机记忆采样：四档限时可行性检查

日期：2026-09-11。按用户要求先对每个数据量采样测速，没有展开多随机数据集平均的正式矩阵。

## 协议

8→16→16→1 tanh，433参数，0/1输入，标准Gaussian神经坐标；权重与偏置沿用原fan-in缩放。每档4副本×1024粒子，pCN约束SMC，2轮尺度适应及8轮固定尺度更新，每轮4个参数块。这是明确降低粒子数与更新量的pilot，不声称与原8副本×4096粒子的精度相同。
一份独立均匀随机的256位标签表，输入随机排列，各n取嵌套前缀。先每档60秒；保留首轮记录后，利用原断点延长至每档最多累计300秒，并以BCE=0.05为本次pilot停止目标，从先验开始，逐级尝试BCE 0.70、0.69、0.65、0.60、0.50、0.40、0.30、0.20、0.10、0.05、0.025、0.01。没有额外hard-fit门槛，没有未见输入标签约束，没有训练anchor或NNGP。

## 怎么解读难度

- 有限窗口采样确实可以推进，64样本的0.1/0.05节点分别约47.3/57.4秒。
- 数据量大时，单层计算变慢，同时达到相同loss所需SMC层数也增加。到0.5的实测耗时依次约13.4、17.4、37.7、55.3秒。
- 不能用浅区间速度线性外推到0.01；越往下，提议尺度、混合与所需层数都可能变化。
- 已用实际耗时检查共同有限窗口的成本；正式多随机数据平均仍未展开，粒子/更新数量的精度复核也未全面进行。
- 副本共用自适应阈值与提议尺度，标准差只是内部诊断，不能当作严格置信区间。
- 末端初始祖先仅剩1至2个/副本，保留为谱系诊断。深层SMC出现祖先合并并不自动证明结果错误，但接受率约0.3同样不能证明已经充分跨模态混合。

## 核验与记录

原采样核心未改写。独立NumPy前向loss核验与一层SMC断点重放逐位一致。共复算5504组保存参数，最大logit差9.69e-06，分类符号变化0个。
额外用262144组独立Gaussian先验参数核对0.70/0.69两浅节点，耗时0.35秒，结果在prior_calibration.csv；没有把浅层校准升级为低loss质量认证。
硬件为本地RTX3080 cuda:1，PyTorch2.11.0+cu130，float32，关闭TF32及AMP。四档采样循环累计680.79秒，不含导入、初始化、工程核验和最终归档。
