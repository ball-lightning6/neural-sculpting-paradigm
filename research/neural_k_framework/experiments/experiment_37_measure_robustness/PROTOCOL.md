# 输出联合分布实验协议

日期：2026-09-19

脚本：[run_output_box_experiments.py](run_output_box_experiments.py)

## 实验目的

本轮把四个效应分开：

1. 输出目标整体平移是否只是输出空间的平移坐标；
2. 去掉最后一层 `output bias` 后，隐藏层 bias 是否能够补偿；
3. 输出类别间距变小时，函数区分度和简单性偏置是否减弱；
4. 规则排序改变时，是收缩系数改变，还是复杂度偏好方向改变。

所有条件都使用 3bit 到 1bit 的完整真值表和原始输出 MSE。输出编码为

\[
y_i=c+a(2f_i-1),
\]

其中 `c` 是输出中心，`a` 是两类输出的半间距。`(-1,+1)` 对应
`c=0,a=1`，`(9,11)` 对应 `c=10,a=1`。

## 四组实验

### 1. 同步平移

运行 `RUN_PLAN = "translation"`。

包含三个条件：

| 条件 | 目标中心 | 输出参考测度中心 | 作用 |
|---|---:|---:|---|
| `center0_base` | 0 | 0 | 基准 |
| `center10_sync` | 10 | 10 | 目标和测度同步平移 |
| `center10_target_only` | 10 | 0 | 只平移目标的控制 |

真正要比较的是共同 MSE 阈值下的：

- `neural_k_bits_median`；
- `centered_output_rms`；
- 函数分布熵和函数支持数；
- 规则间 K 排序。

预期：同步平移条件的中心化曲线和 K 排序应近似重合。只平移目标会额外支付测度代价，可能明显变慢或在有限预算内无法进入深尾。

### 2. 最后一层 bias 对照

运行 `RUN_PLAN = "bias"`。

两个条件保持隐藏层 bias 不变：

- `output_bias_on`：完整网络；
- `output_bias_off`：只删除最后一层输出 bias，参数数目从 81 变为 80。

这里不把 `output_bias_off` 的输出中心移到 10，因为那会重新人为加入一个外部平移。重点是比较中心为 0 时：

- 完整输出体积曲线；
- 中心化输出体积曲线；
- 函数分布是否仍能凝聚到同样的规则；
- 深尾斜率是否改变。

如果 output bias 主要只是全局平移自由度，那么中心化曲线应比未中心化曲线更接近。若两者仍明显不同，说明隐藏表示和可达性也参与了变化。

### 3. 输出幅度扫描

运行 `RUN_PLAN = "amplitude"`。

扫描

\[
a\in\{0.01,0.1,0.5,1,3\},
\]

即比较 `(-a,+a)`。这里使用绝对 MSE，不把 loss 除以 `a²`，因为要直接观察目标幅度对函数区分度的实际影响。

需要同时看：

- K 随 `-log10(MSE)` 的全曲线斜率；
- 最后四个节点的深尾斜率；
- 规则间 K 的排序相关；
- 输出中心化 RMS；
- 函数分布熵和支持数。

`curve_summary.json` 会自动报告全曲线斜率和深尾斜率。斜率单位是 bit/decade，即 MSE 每下降十倍时 K 增加多少 bit。

### 4. 合并运行

运行 `RUN_PLAN = "all"`，依次执行以上三类实验。它适合在小规模试跑确认后使用，不建议第一次就运行。

## 规则与统计

默认规则为：

- `0x00`：常数函数；
- `0x0F`：单输入 copy；
- `0x17`：三输入多数型规则；
- `0x69`：parity3。

若只检查机制，可改为 `RULE_IDS = (0x00, 0x0F)`。若要增加排序稳定性，再加入其它完整规则；不建议一开始穷举全部256条规则。

每条曲线保存四个独立 SMC 副本。正式结果不会把未到达的阈值外推。`float64_max_excess` 用于检查 float32 粒子是否越过 MSE 边界。

## 硬件建议

| 运行规模 | 建议设备 | 说明 |
|---|---|---|
| 语法和小规模自检 | CPU 或 3080 | 可把副本改为2、粒子改为64 |
| `translation`，4条规则 | 本地3080足够 | 3bit、宽度16、单隐藏层，参数约81个 |
| `bias`，4条规则 | 本地3080足够 | 只增加一组参数布局对照 |
| `amplitude`，4条规则 | 本地3080可做 | 曲线数量较多，时间预算可先保持180秒 |
| `all` 或增加到8副本、4096粒子 | 5090更合适 | 主要为了降低深尾统计误差，不是显存需求 |
| 4bit或全部65536条规则 | 5090优先 | 先不要和本轮3bit机制验证混在一起 |

脚本自动记录 GPU 型号、PyTorch 版本、内核 hash、脚本 hash、SMC预算和每条曲线耗时。

## 结果解释边界

同步平移重合只能证明输出空间中的平移协变性，不能证明所有架构和所有 loss 都具有相同的测度。幅度扫描中若规则排序保持而斜率改变，支持“复杂度顺序较稳健、压缩强度依赖输出编码”的修正；若排序也改变，则说明输出联合分布会改变架构诱导的复杂度偏好。

`target_probability` 只描述当前 SMC 粒子中的函数映射占比，不等于训练后的测试准确率。最终仍需把 K 曲线、中心化输出统计和规则对齐结果一起看。
