E11: Rule-30 Train/Validation Gradient Alignment across Dataset Size

Measure how more rule-consistent data changes the direction of loss descent at matched training-loss levels.

Scripts
experiment_rule30_train_val_gradient_alignment.py

Experiment overview

Purpose

E11 tests whether increasing the number of training samples for the same rule only changes the final generalization endpoint, or whether it systematically changes the directional relationship between the raw training gradient and the independent validation gradient at approximately matched raw BCE levels. The frozen implementation selects the nearest checkpoint by log-loss distance, allows at most a 1.35-fold loss discrepancy, and does not interpolate.

It provides local gradient-geometric evidence for the claim that "a finite training set only supports rule-aligned descent to a finite loss depth; the more data, the deeper that channel extends"; the first-order prediction for a small step along the negative raw training gradient is not the effect of an actual Adam update.

Why this experiment was run, and how it was judged

1. Question

In synthetic tasks with sufficient data, train and validation loss often decrease in lockstep from early in training. One overly strong explanation is that "the high-loss region is already almost entirely populated by correct functions"; a more local, measurable explanation is: the more data, the closer the training gradient is to the population rule gradient, because training-set-specific directions cancel out more fully under sample averaging.

A single small-learning-rate SGD update along the negative raw full-train gradient satisfies the first-order approximation:

$$ \Delta L_{val} \approx -\eta\nabla L_{val}\cdot\nabla L_{train}. $$

The train/validation gradient cosine therefore gives a first-order prediction of the validation-loss change for a small step along the negative raw training gradient. Adam's momentum and adaptive preconditioning change the update direction, so this cosine cannot be directly interpreted as the validation-loss change from an actual Adam step; that requires a separate measurement.

2. Formal configuration

  • Task: 30-bit Rule 30 one-step update with cyclic boundary, output 30 bits;
  • Network: 30 -> 1024 x 3 -> 30 GELU+LayerNorm;
  • Training samples: 256, 512, 768, 1024, 1280, 1536, 2048, 4096, strictly nested;
  • Independent validation: 4,096;
  • 5 paired model seeds, 40 models in total;
  • Adam, learning rate 1e-3, batch 512;
  • Both dropout and weight decay are 0;
  • Maximum 20,000 steps.

3. Three gradient metrics

  • train_validation_gradient_cosine: full-gradient cosine between training and independent validation;
  • train_half_gradient_cosine: gradient coherence between the two halves of the training set;
  • validation_half_gradient_cosine: a consistency reference line from the two halves of validation.

The third item is only a reference for finite-validation sampling noise, not a strict mathematical upper bound.

4. Key control: matched raw BCE

Different sample sizes reach different losses at the same step, so they cannot be compared directly. For each sample size and seed, the frozen implementation selects the saved diagnostic checkpoint nearest to each of the following target losses by log(raw BCE) distance, without interpolation:

0.68, 0.6, 0.5, 0.4, 0.3, 0.2,
0.1, 0.05, 0.02, 0.01, 0.003

Only matches satisfying max(actual_loss / target_loss, target_loss / actual_loss) <= 1.35 are retained, and the gradient cosine and validation-train BCE gap are then compared level by level. This is a nearest-checkpoint comparison with a tolerance, not an exact same-loss comparison; the archived fixed_raw_bce_comparison.csv retains each point's actual loss and actual/target ratio.

5. Preregistered predictions and boundaries

If the sample size reshapes more than the endpoint, then at the same raw BCE, the more training samples there are:

  1. the higher the train/validation gradient cosine;
  2. the smaller the generalization gap;
  3. this ordering should be preserved across seeds;
  4. the low-data condition can turn to negative cosine at deep loss, while the high-data condition remains positive.

This experiment uses only one nested data permutation and one task, and does not establish a cross-task universal law; when the gradient norm approaches numerical zero the cosine loses meaning, so the main analysis uses target BCE levels no lower than 0.003, with actual checkpoint losses subject to the tolerance above.

Results, interpretation, and limits

1. Completeness

  • 8 sample sizes, 5 seeds, 40 models in total;
  • All runs lasted 20,000 steps, with a total wall time of 313.3 seconds;
  • The same seed has exactly the same initialization across sample sizes;
  • Training sets are strictly nested, and validation is fixed and independent;
  • For each sample size and seed, matched loss selects the nearest checkpoint by log-loss distance, retaining only points satisfying max(actual_loss / target_loss, target_loss / actual_loss) <= 1.35; the historical implementation did not interpolate.

2. Sample-size ordering at approximately matched raw BCE

The archived fixed_raw_bce_comparison.csv shows that, in the nearest-checkpoint matches at target raw BCE 0.2, 0.1, 0.05, 0.02, 0.01, and 0.003, each of the five seeds individually exhibits the complete ordering in which increasing the training sample size strictly increases the gradient cosine. At target 0.3, only 4/5 seeds strictly preserve this ordering; for seed 4 at n=256/512, the actual BCE values are 0.33647/0.26956 and the cosines are 0.178/0.167. These comparisons use the tolerance above, not exactly equal losses.   • n=4096: actual train BCE mean 0.00949, range [0.00858, 0.01074]; cosine 0.950, gap about 0.00137.

The negative cosines observed in the low-data conditions therefore indicate that, at the corresponding diagnostic points, a small step along the negative raw full-train gradient would increase validation loss to first order; a negative group mean does not imply a negative cosine for every seed. At approximately matched deep loss, the high-data condition's raw training gradient remains highly aligned with the independent validation gradient. This does not measure the actual Adam update direction or the actual validation-loss increment; those require separate measurements.

3. A continuum from overfitting to synchronized generalization

  • n=256/512 fully fit the training set at steps 31–50, with final validation bit accuracy about 74.84%/92.96%;
  • n=768 fits the training set at step 67, and validation only exceeds 99% after steps 500–1000, ending at 99.9958%, showing smooth delayed generalization;
  • n=1024 reaches zero error at the end on all five seeds;
  • n=4096 reaches 100% in both training and validation exact accuracy at about step 84, almost synchronously.

Near initialization, even a small amount of data provides a clear Rule 30 shared direction; what the sample size truly determines is how deep into training loss that direction can extend. The shared structure of low data is exhausted earlier, and the remaining gradient turns to training-set-specific details; the remaining constraints of high data stay rule-coherent at low loss.

4. Stage verdict

E11 supports:

Increasing the number of training samples for the same rule not only changes the final generalization outcome, but also systematically improves raw train/validation gradient alignment at diagnostic points with approximately matched raw BCE along the optimizer's actual trajectory, supporting the extension of rule-consistent descent along the negative raw gradient to deeper loss.

It provides a single local geometric explanation for synchronized train/validation descent, smooth delayed generalization, and ordinary overfitting, and it also supports the revised picture that "any finite D typically only supports rule alignment to a finite loss depth."

What cannot be claimed:

  • that the high-loss parameter space is already filled with correct hard functions;
  • that the gradient cosine directly equals function volume;
  • that the raw gradient cosine directly gives the validation-loss change from an actual Adam update;
  • that the validation-half cosine is a strict upper bound;
  • that a single Rule 30 data permutation suffices to establish a cross-task law;
  • that the final cosine is still meaningful when the gradients are numerically near zero.
