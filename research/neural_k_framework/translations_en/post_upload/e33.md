## Default experiment

| Item | Setting |
|---|---|
| Architectures | MLP, RNN, LSTM, Transformer, ViT, ConvNeXt, Swin, U-Net, improved U-Net, Swin-Unet |
| Model size | Reuses the already-benchmarked compact models, 9,800 to 145,250 parameters |
| Rules | One step of 8-bit elementary cellular automaton evolution: Rule 204 identity map, Rule 90 neighbor XOR |
| Training-constraint inputs | The first 16 8-bit inputs under a fixed random permutation, exactly the same for both rules and all architectures |
| Symbol encoding | Inputs 0/1, outputs 8 bits; one token per bit for the Transformer |
| Image inputs | 2×4 black-and-white logical cells laid out row by row in bit order, nearest-neighbor upscaled to 32×32, identical across the three RGB channels; no gray interpolation, no grid lines, no sample-ID watermark |
| Image outputs | The three U-Net-type models natively output 32×32 images; the other models output 8 numbers |
| Observations | All models measure cell-wise mean BCE and cell-wise max BCE; the three image-output models additionally measure whole-image native-MSE |
| SMC | Four independent replicas, 128 particles each; all learnable parameters participate, hidden layers are not frozen |
| Targets | BCE down to 0.001; native-MSE down to 0.0001 |
| Default budget | 180 seconds per replica per item; one sampling loop runs at most 8 hours, with saving/packaging overhead counted separately |
| Queue | Let every architecture obtain its first replica first, then fill in round by round; do not run one architecture all the way to the end |

Cell-wise mean BCE is the average over 16×8 elements. Max BCE corresponds strictly to a lower bound on the minimum signed margin over these cells; **it is not a thin slice where all samples have equal magnitude**.

The plain U-Net uses the raw-output MSE from the original training file; the improved U-Net and Swin-Unet use post-sigmoid MSE. native-MSE constrains all pixels and must not be conflated with the absolute K of BCE, which constrains only 8 cells.
For image models, the "full bit map" means the decoding at the 8 designated cells over all inputs, not a hard map of the entire 1024-pixel image; whole-image MSE and pixel accuracy are recorded separately.

The default 16 inputs are a fixed-D measurement, not the full-rule Neural K. Each loss node additionally observes outputs on all 256 inputs, but these extra labels **do not enter the SMC target, and are not used for stopping or for selecting particles**.
When a full-rule constraint is needed, set `POINTS=256` and set a separate `RUN_TAG`; the benchmarking budget for 16 inputs must not be carried over directly to 256 inputs.

## Pausing and resuming

- Ctrl+C once: save and package after the current SMC level finishes; a second forced interrupt restores the last complete checkpoint and does not save a half-finished level.
- You can also create a `STOP` file in the results directory; remove it before running again.
- Exceeding the per-replica budget: save that item and switch to the next one. The next run continues from the breakpoint, not from the prior.
- Items that have already reached the target are skipped directly, with no automatic recheck.
- Checkpoints are still retained after completion; changing `STOP_BCE`/`STOP_MSE` to a lower value in the preset grid lets you keep sampling deeper.

## Reliability

This is a fully automated **finite-loss first measurement**; the 128 particles are not claimed to be precise deep-tail ground truth.

Independent replicas, direct prior calibration, acceptance-rate/step-size alarms, complete logging, and engineering tests are used to find problems; the absence of alarms does not prove sufficient mixing. SMC particles are correlated with each other, so within-package agreement is not the agreement of independent SGD seeds.
Higher precision should only be pursued in a separate recheck with more particles or a larger update budget for selected rules/architectures; this version does not automatically rerun all curves.

The prototype and the formal version keep the same model/target/reference measure. The runner additionally avoids meaningless resampling when all particles are alive, and makes node decisions use the same rounding convention as the actual float32 thresholds; nominal and effective thresholds are both recorded.
These engineering changes alter random trajectories; the formal SMC is not treated as a continuation of the three-level state from benchmarking.

## Overall assessment

This round has obtained substantive cross-architecture measurement results, no longer just benchmarking.
The clearest signals are: different architectures give very different function preferences under the same training constraints; for several architectures the complete low-loss curves reproduce across four independent replicas; and rule pairs that can be jointly compared show volume/contraction differences in a consistent direction.
But this is still a 128-particle finite-loss first measurement: some routes only have time-truncated results or clear replica disagreement, and it is not claimed that all architectures have passed precise deep-tail verification.

**The object definition must be preserved: what is measured here is the `K_D` for 16 fixed inputs, not the full-rule `K_f` constrained on all 256 inputs.**
Rule204/90 are the names of the rules generating the two sets of constraint labels; inside each curve there are still all candidate bit maps satisfying that training set.
For image models, the "full bit map" only reads the 8 designated cells of each input image; whole-image metrics are listed separately.

- Direct prior calibration did not trigger the existing heuristic alarms, but this does not certify deep-tail mixing.

## Common direction across the rule pair

For each architecture, comparison is made only at the **deepest common node reached by both rules and all four replicas**.
All ten architectures have `K_D90 > K_D204`, and for each architecture all four Rule90 estimates are higher than all four Rule204 estimates.
Among them, the Transformer can only be jointly compared down to 0.6, ViT to 0.3, and the plain U-Net to 0.4, so these comparisons must not be described as their deep-tail conclusions.

For the four architectures where both rules had all four replicas reach BCE=0.001, the coefficients over the last halving window are:

`c = [K_D(0.001)-K_D(0.002)] / log2(2)`, computed by first taking the difference within the same replica, then the median across replicas; ± is the replica SD.

| Architecture | c for Rule204 | c for Rule90 |
|---|---:|---:|
| MLP | 348.39 ± 10.82 | 405.43 ± 5.50 |
| RNN | 636.19 ± 6.34 | 677.03 ± 7.13 |
| ConvNeXt | 343.12 ± 6.28 | 370.81 ± 13.67 |
| Improved U-Net | 17.46 ± 1.25 | 57.16 ± 3.57 |

This supports a limited-scope cross-architecture result: on the training constraints generated by this pair of preselected rules, the conditioning on the more complex Rule90 not only has smaller volume, but also contracts faster in the final window.
This cannot be upgraded to the claim that all full functions satisfy the same complexity law; only one pair of rules was measured here, and the object is the training-set conditional volume.

|---|---:|---:|---:|

The numbers are the empirical distribution of correlated SMC particles, not 512 independently trained models. 0/512 does not mean the true conditional probability is strictly zero.
"Improved U-Net" is only the version name from the old code and does not mean it should be comprehensively better than the plain U-Net on this measurement.

For Swin-Unet, clear Rule204 condensation already occurs in a shallower region:

| Mean BCE cap | Fraction of full-Rule204 particles |
|---|---:|
| 0.7 | 2.9% |
| 0.6 | 13.3% |
| 0.5 | 32.4% |
| 0.3 | 78.9% |
| 0.1 | 99.8% |
| 0.03 and below | 100% |

This directly shows that in the sampled static conditional distribution, the rule cluster can condense as the constraint tightens.
At the same time, MLP, RNN, and others still contain a large number of different extrapolations, showing that adequate fitting and function condensation are not the same thing.
The RNN's end-window contraction coefficient for Rule90 is about 677 with replica SD of only about 7, yet its unseen-bit accuracy is about 52% and its function entropy is close to the 7-bit ceiling that 128 particles can display; the target full map was not sampled.
So a stable macroscopic contraction curve does not mean the function distribution has already condensed, and one cannot infer from it that the complexity of every candidate function has been measured one by one.

![Volume and full-rule recovery](E:/code/clean_github/neural-sculpting-paradigm/tmp/cross_architecture_rule_volume_analysis_20260912/03_copy_volume_and_function_recovery.png)

The absolute `K_D` across architectures is not a generalization score: for example, the RNN's `K_D` is higher than the MLP's, but its unseen-bit accuracy is also higher.
To explain generalization, one still needs to look at the relative mass of different function clusters inside that conditional region.
What is compared here is the combination of architecture, input encoding, readout design, and an explicit Gaussian reference measure, not a ranking of the architectures' general capabilities.

## Not all coefficients have become constant

Over the fixed 0.01-to-0.001 interval, comparing the first and the last adjacent windows:

- The coefficients of MLP and ConvNeXt still increase by about 20%.
- RNN increases by about 9% to 18% on both rules; Transformer/Rule204 by about 18%.
- The Rule204 coefficients of the plain U-Net and Swin-Unet decrease by about 18% to 21%.
- The two curves of the improved U-Net change less, decreasing by about 2% and 6%.

Therefore the more accurate statement is: measurable, usually smooth, architecture-dependent contraction profiles have appeared, within which some window coefficients are relatively stable; it is not the case that all architectures have already arrived at the same constant-slope deep tail.
The `a=-log(expm1(epsilon))` converted from mean BCE is only a coordinate reparameterization and does not mean all cells truly have equal magnitude.
The straight-line fits over the fixed interval are saved in `tail_fits.csv`; high R² is not treated as an asymptotic law or as certification of mixing.

## What was measured this round

Following the model list from Act VI of the old paper and the image tasks, ten deterministic models have been wired in.

These new architectures have not yet been measured on the 5090, so no precise GPU speedup multiplier can be given. The table below is computed only under the wide budget assumption that **the 5090 is 1 to 3 times the current 3080 speed**; it is not a verified performance range or upper bound.
On the same 5090, CPU scheduling, CUDA/PyTorch versions, and operator shapes also affect speed.

Assume one curve needs 1000 adaptive SMC levels, 4 independent replicas run sequentially, 128 particles per replica:

| Model | 5090 budget scenario (1 to 3x speed) |
|---|---:|
| MLP | about 12 to 35 minutes |
| RNN/LSTM | about 16 to 70 minutes |
| Transformer/ViT/ConvNeXt | about 0.5 to 1.9 hours |
| Swin | about 1.3 to 3.8 hours |
| Swin-Unet | about 2.9 to 8.6 hours |
| Both U-Nets | about 4.3 to 16.8 hours |

1000 layers is not 1000 loss-recorded nodes; it is the iteration budget of the entire adaptive path.
**It is currently unknown how many layers are needed to reach 0.01 or 0.001, let alone after how many layers mixing is already sufficient.**
If only 200 layers are needed, multiply the table by about 0.2; if 5000 layers are needed, multiply by about 5. Increasing the particle count or the number of fixed update rounds also increases the cost.
The 64×64 input images and 16 inputs are part of this estimate; it cannot be extrapolated to the original paper's 224×224, tens-of-millions-of-parameters, or full-256-input settings.

Ten architectures × two rules × two BCE constraints × four replicas, 1000 layers per replica, comes to about 200 hours at the 3080 speeds measured this round; under the above 5090 scenario, about 67 to 200 hours, **still without counting whole-image MSE, long checkpoint IO, or a stronger mixing budget**.
Therefore it is not recommended to chase the deep tail directly on this entire matrix.

## Memory and disk

Four replicas run sequentially, so memory is not multiplied by 4. At the current 128 particles, the largest model already fits in a 10GB card, so the current model sizes have no hard memory obstacle.
But when the particle count is increased to 512, the main particle/proposal cost of Swin-Unet is about 4 times the current one, so one cannot take it for granted that it can be scaled further to several thousand particles.

If the full matrix keeps all unfinished-replica checkpoints, including the extra native-MSE tasks of the image models, the theoretical total particle-file size is about 161 GB.
The four-replica checkpoints of a single Swin-Unet curve are about 8.9 GB. Therefore runs must be batched and active checkpoints controlled, rather than directly applying the "small result package" experience of the small MLP.
The script zip excludes the full `.pt` files, but the raw checkpoints on the server still actually occupy disk. Whether to keep them after completion is explicitly decided by configuration.

## Recommended next steps

1. Keep the model sizes and first shrink the matrix: MLP, Transformer, Swin-Unet, still retaining genuinely different fully-connected / attention / hierarchical image encode-decode mechanisms.
2. For the first run, take two rules, two BCE constraints, two replicas, and at most 200 layers per replica, to locate the reachable loss and obvious sampling disagreement. Under the above 5090 speed scenario, about 1.4 to 4.3 hours, extra IO not included.
3. This is a measurability screening; do not directly claim a deep-tail law from 128 particles and two replicas. First check whether there is enough loss span and rule difference, then add particles or a fixed update budget to a small number of curves.
4. The image models additionally measure whole-image native-MSE. The cell-BCE measurement only constrains the centers of 8 cells and cannot be treated as image quality or whole-image volume; the plain U-Net original script is raw-MSE, and the improved U-Net/Swin-Unet is sigmoid-MSE — kept separate.
5. What is compared is the architecture geometry under an explicit Gaussian reference measure. BN is in eval with running statistics fixed; the priors of normalization parameters and residual gates are listed separately and are not claimed to be equivalent to the random initialization / SGD distribution of the old training scripts.
