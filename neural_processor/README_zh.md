# 神经处理器脚本 (Neural Processor Scripts)

本目录包含用于生成和运行神经处理器数据集及模型的脚本。

## 项目状态与局限性说明 (Project Status & Limitations)

**这是一个非常初步的尝试，投入的时间也相当有限。**

本项目的核心出发点源于这样一个观察：在这个范式下训练“输入到输出”的直接变换时，如果中间步骤过多，训练会变得异常困难。这让人联想到之前训练迷宫任务时，直接预测“起点到终点的最短路径”非常困难，但如果改为预测“最短路径的最优下一步”，效果就会好很多。这启发了我们：**解决一个困难的、可能非定长的最优解决方案问题，可以转化为一个定长的“最优通过单步”问题。**

基于此，我们产生了这样一个想法：如果可以模拟一个成熟的 CPU 内核，那么理论上我们可以通过多次单步模拟来解决任何可计算问题。这就是本项目“神经处理器”想法的由来。

然而，这个想法面临一个核心挑战：**Neural CPU 的精度如何？**
- 在实际训练中，使用 RTX 4090 显卡，在大约 1 天的时间内，可以将单 bit 的预测精度提高到约 **99.9999999% (9个9)**，整体输出的状态精度提高到约 **99.99999% (7个9)**。
- 这样的精度足以支撑一些简单的、短流程的问题计算。
- 为了进一步提高精度，我们曾尝试了**投票法**，但发现其效果并不显著。分析原因可能是因为不同模型实例出错的模式是相似的（非独立错误），这可能与训练数据的分布特性有关。

**关于未来的设想：**
理想的架构应该是**模块化**的：不仅 CPU 内核由神经网络模拟，**内存存取模块**显然也可以通过神经网络来模拟。程序执行的过程将是：Neural CPU 执行指令 -> 读取/存入内存 -> 循环往复，直到 CPU 输出 Halt 指令中断执行。

虽然目前我们没有继续深入投入时间，且该项目后续的具体应用场景尚不明确，但它作为一个**概念验证 (Proof of Concept)**，成功证明了这种“神经指令集计算机”是可以运行简单程序的。

## 设计哲学与架构思想

本项目旨在探索将神经网络即作为**算术逻辑单元 (ALU)** 甚至完整的 **CPU** 来执行经典计算机程序的可能性。

1.  **混合架构 (Hybrid Architecture)**: 
    -   经过早期尝试完全由神经网络管理所有状态和内存后，发现训练难度会随复杂度指数级上升。
    -   因此，本项目最终确立了一种**混合设计模式**：由 **Python 脚本**充当经典的“控制器” (Controller)，负责指令获取、程序计数器 (PC) 跳转、内存读写管理和 I/O；而**神经网络**则作为一个被调用的“黑盒 ALU”，专注于执行核心的逻辑运算和状态转换。这种设计既保留了传统架构的精确控制流，又利用了神经网络的学习能力。
    -   未来的理想形态可能是：Neural CPU 负责计算 -> 内存模块负责读写 -> 循环直至停机信号。

2.  **关于“神经投票器” (Neural Voter)**:
    -   曾尝试使用集成学习（投票法）来提高 Neural CPU 的精确度。
    -   然而实验发现，不同模型实例犯错的模式往往不是独立的 (Non-i.i.d. errors)，导致简单的多数投票法提升有限。
    -   因此，提高可靠性的关键在于改进训练数据和架构本身，而非单纯依赖后处理投票。这也解释了为什么本项目最终转向了更精细化的单体模型训练。

3.  **演进路线**:
    -   从最基础的加法器 (v1)，进化到带有内存和跳转的微处理器 (v2)，再到为特定算法 (GCD) 定制的专用核心 (v2.1) 和图灵完备的通用核心 (v2.2)。

## 训练数据生成 (Training Data Generation)

### 1. `generate_cpu_v1_basic.py`
- **用途:** 这是一个基础的**神经CPU原型**，旨在验证神经网络能否学习执行最基本的指令集。
- **ISA定义:**
    - **状态:** 4个8-bit寄存器。
    - **指令集:** `NOP`, `MOVI` (立即数赋值), `ADD`, `XOR`。
    - **架构:** 16-bit指令长度。
- **I/O格式:**
    - 输入: 指令 (16b) + 当前状态 (32b)。
    - 输出: 下一状态 (32b)。
- **主要参数:** `DATASET_SIZE`, `NUM_REGISTERS`。
- **状态:** 已验证 (基础功能验证通过)。

### 2. `generate_cpu_v2_microprocessor.py`
- **用途:** 这是一个功能更完整的**神经微处理器**，引入了**内存访问**和**控制流**指令，模拟了冯·诺依曼架构的核心特征。该脚本用于训练一个不仅能计算，还能进行数据存取和程序跳转的模型。
- **ISA定义:**
    - **状态:** 8个8-bit寄存器 + 1个标志位 + 16字节内存。
    - **指令集:** `LOAD`, `STORE`, `ADD`, `SUB`, `CMP`, `JMP`, `JLT` (条件跳转), `PRINT` 等。
    - **架构:** 24-bit指令长度。
- **I/O格式:**
    - 输入: 指令 (24b) + 完整机器状态 (寄存器+标志+内存)。
    - 输出: 更新后的完整机器状态。
- **主要参数:** `DATASET_SIZE`, `MEM_SIZE`。
- **状态:** **已验证**。在 `run_rainwater_program.py` 中成功运行了接雨水算法。

### 3. `generate_cpu_v2_1_gcd.py`
- **用途:** 这是一个**专用型神经ALU**，其指令集被裁剪和优化以专门支持**最大公约数 (GCD)** 算法的执行。
- **ISA定义:**
    - **状态:** 4个8-bit寄存器 + 2个标志位 (ZF, GF)。
    - **指令集:** `MOVI`, `MOV`, `SUB`, `CMP`。
- **实验意义:** 验证了通过精简指令集，神经网络可以极其高效地学会特定的算法原语。该模型在后续的 `run_gcd_program.py` 中被证明能以100%的准确率执行欧几里得算法。
- **状态:** **已验证**。此模型在 `run_gcd_program.py` 中验证了执行欧几里得算法的准确率为100%。

### 4. `generate_cpu_v2_2_universal.py`
- **用途:** 这是一个**通用型神经ALU**，拥有图灵完备所需的几乎所有基础指令。它是本系列中最强大的通用计算核心。
- **ISA定义:**
    - **指令集 (扩展版):** 包含算术 (`ADD`, `SUB`, `INC`, `DEC`)、逻辑 (`AND`, `OR`, `XOR`, `NOT`)、移位 (`SHL`) 和控制 (`CMP`) 指令。
- **实验意义:** 在 `run_bubble_sort_program.py` 中，该模型展示了强大的泛化能力，能够成功执行复杂的冒泡排序算法。
- **状态:** **已验证**。在冒泡排序端到端测试中取得了100%的准确率。

### 5. `generate_cpu_v3_pi.py`
- **用途:** 这是一个**高精度计算专用ALU**，引入了进位 (Carry) 和借位 (Borrow) 标志，支持多精度算术运算，旨在让神经网络具备计算 Pi 等高精度数值的能力。
- **ISA定义:**
    - **状态:** 16-bit寄存器 + 3个标志位 (ZF, GF, CF)。
    - **指令集:** `ADC` (带进位加), `SBC` (带借位减) 等。
- **设计意图:** 解决标准神经网络难以处理超长整数运算的问题，通过学习进位链逻辑来实现任意精度的数学计算。
- **状态:** **实验性**。已提供数据集生成脚本，但尚未验证使用此特定架构进行端到端的程序执行。

### 6. `generate_voter_dataset.py`
- **用途:** 生成用于训练“神经投票器”的数据集。该模块旨在通过集成学习（Ensemble Learning）的思想，利用多个神经处理器的预测结果进行投票，以纠正单点错误。
- **逻辑:** 模拟多个有一定错误率的预测器的输出，并以多数投票作为真值标签。
- **注:** 后续研究发现神经处理器的错误往往具有相关性（非独立同分布），因此简单的投票策略提升有限，该模块更多作为一种探索性的历史记录。
- **状态:** **实验性**。仅为概念实现；未集成到主要执行流程中。

## 验证与运行 (Verification & Execution)

### 7. `run_gcd_program.py`
- **用途:** **端到端验证脚本**。它加载训练好的 `cpu_v2_1` 模型，验证了该专用核心执行 GCD 算法的能力。
- **架构实现:** 典型的“Python控制器 + 神经ALU”混合模式。
- **验证结果:** 在测试中达到了 **100%** 的程序执行准确率。

### 8. `run_rainwater_program.py`
- **用途:** **端到端验证脚本**。它驱动 `cpu_v2_microprocessor` 执行 LeetCode 困难题 —— **接雨水 (Trapping Rain Water)** 的双指针算法。
- **复杂度:** 相比 GCD，该程序涉及了更复杂的内存读写 (`LOAD`/`STORE`) 和指针操作，验证了神经微处理器处理复杂数据结构的能力。
- **结果:** 验证成功。

### 9. `run_bubble_sort_program.py`
- **用途:** **端到端验证脚本**。驱动 `cpu_v2_2` (通用版) 模型执行**冒泡排序**算法。
- **验证结果:** Log显示其在对3个随机数进行排序的任务中达到了极高的准确率，证明了通用神经ALU对比较交换逻辑的完美掌握。

### 10. `debug_gcd_program.py`
- **用途:** `run_gcd_program.py` 的**单步调试版本**。它不仅运行程序，还会详细打印出每一步的 PC 指针、指令、执行前的状态、神经网络的预测输出以及真值的对比。用于深度分析模型在哪个具体指令或状态下可能出错。
