01

精确真值由独立 ISA 实现生成

训练目标不来自神经核心自身，而由独立、精确的 ISA 真值实现生成；损失是所有输出 bit 的 BCE。

  1. 按生成器规则采样输入

    指令字段、寄存器值和标志位随机产生，32 个 opcode 在 batch 内保持均衡。

  2. 独立精确实现计算目标

    一个与神经网络无关的精确 ISA 实现算出下一时刻的标志位、寄存器与控制信号。

  3. 逐位计算 BCE

    网络输出与精确目标在所有输出 bit 上计算二分类交叉熵损失。

02

基础随机分布与 opcode 均衡

  • 每个 batch 内 32 个 opcode 保持均衡；
  • 指令字段、寄存器值和标志位按生成器规则随机产生。

但只按 opcode 均衡还不够——见下文“结构状态”一节。

03

从普通训练到 hard replay

普通随机训练始终保留，hard replay 只占 batch 的 12.5%。hard replay 内既包含已知算法边界样本，也包含由独立大规模审计动态分配的 opcode 与结构状态样本。

04

动态审计 → replay 循环

  1. 随机生成训练 batch
  2. 常规训练
  3. 定期独立审计每个 opcode 与结构状态
  4. 计算风险并做 EMA
  5. 更新下一阶段 replay 比例
  6. 继续保留大部分原始随机分布

    回到循环起点；hard replay 始终只占 batch 的 12.5%。

风险分数结合平均 bit BCE 与 sample exact error rate；风险取平方根后分配 replay 权重，避免权重过度振荡；20% 的均匀分布防止较容易的 opcode 被完全遗忘。

05

为什么需要结构状态

随机验证中，绝大多数状态的 35 个状态 bit 约有一半为 1；但真实程序轨迹经常经过全零、近全零、常量初始化、清空后的寄存器等结构化状态。

实际运行 pi 程序时，早期模型在零很多的状态上暴露出远高于全局随机验证的错误率；对称地，接近全 1 的状态也可能构成另一类边界。因此训练中加入两个“虚拟 opcode”式的结构组：

组35 个状态 bit 中 1 的数量
SPARSE_STATE0 – 8
DENSE_STATE27 – 35

这两个名字只是采样与审计分组（“虚拟 opcode”），不是 ISA 中真实存在的指令。

06

best 与 balanced 的选择标准

训练脚本会保存两个候选 checkpoint，选择标准不同：

checkpoint选择标准
best_model.pt优先最小化普通固定验证集的平均 loss
best_balanced_model.pt按更严格的字典序依次比较下列三项
  1. 普通与结构验证组的 exact error 总数
  2. 所有真实 / 虚拟组中的最坏 loss
  3. 总体平均 loss

发布版只提供 best_balanced_model.pt（weights/neural_cpu_v3_best_balanced_model.pt）。

两个模型通常非常接近，但 balanced 版本更适合真实程序轨迹，也可作为继续训练的起点。
