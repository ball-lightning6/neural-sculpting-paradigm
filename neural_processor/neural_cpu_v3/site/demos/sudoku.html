求解器怎样映射到 16-bit ISA

求解算法完全写成项目 ISA 的机器码：MRV（最少剩余候选）搜索、显式回溯栈和对每格 20 个 peer 的扫描都由指令流实现。每个候选数字都由程序扫描该格的 peer 后判定。

棋盘、候选搜索状态和回溯栈位于 64 KiB RAM；脚本还定义了一组低地址命名单元（如 DEPTH、BEST_CELL、POINTER_LOW / POINTER_HIGH）保存搜索状态。固定的 peer 表由 Python 提供。

神经侧

Neural CPU 承担什么

神经核心 · MLP

求解过程中由神经核心逐条完成的状态转移包括：

  • 候选计数、MRV 比较与选择的寄存器算术；
  • 回溯栈与指针单元的读写控制和相关算术；
  • peer 扫描循环的条件判断与分支；
  • 标志位（ZF、GF、CF）与 memory_read / memory_write / branch_taken / halt 控制信号。
外部侧

外部运行时承担什么

外部精确组件

  • 装入题目：从 assets/project_euler_096_sudoku.txt 无放回抽取 10 道；
  • 提供固定的 peer 表（每格 20 个 peer）；
  • 显示棋盘并最终验证答案；
  • PC、取指、64 KiB RAM 读写，以及 batch 模式下的轨迹生成与 GPU 调度。
验证口径

三种模式

同一个求解器可以以三种方式运行或审计，区别在于是谁推进状态、以及是否加载神经权重。

模式含义
exact 不加载权重，只运行精确实现，验证求解器和机器码。
serial 神经核心自主执行单条依赖轨迹。
batch 默认模式。逐题生成该题的精确轨迹，然后分块批量审计 Neural CPU 的每一步。

默认行为：随机抽取 10 道题，逐题生成轨迹并用 GPU 大 batch 审计。

运行方法

所有可调参数集中在脚本顶部的 Config。在 neural_cpu_v3/ 目录下运行：

python scripts/run_neural_cpu_v3_sudoku.py
参数默认值说明
MODE"batch""exact" / "serial" / "batch"
PUZZLE_COUNT10从 50 道题中无放回抽取的题数
PUZZLE_INDEXES""逗号分隔的题号；设置后按题号选题
PUZZLE""自定义题目字符串；设置后只解该题
RANDOM_SEED""选题随机种子；留空则每次随机
MAX_NEURAL_OPERATIONS1_000_000_000神经操作步数上限

边界

限制与不声称的内容

  • 180,243,530 次操作是一次已记录运行的结果。单题难度不同，操作数会有明显差异，它不是固定成本。
  • 0 神经错误针对该次已记录运行；随机单步错误率的数量级口径见可靠性页。 可靠性页 →
  • batch 是先由精确实现生成每道题的唯一轨迹、再逐步审计神经核心，不是神经网络并行求解许多不同题目，也不是把答案从外部喂给网络。
  • 答案由 Python 侧最终验证；0 神经错误指神经执行与精确真值逐步一致，两者是不同口径。
