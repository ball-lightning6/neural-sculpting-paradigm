分段奇数筛怎样映射到 16-bit ISA

筛法的全部决策都编译进 16-bit 指令流：基础质数、p²、筛缓冲区地址、跨分段的下一个倍数、质数计数和停止条件都由指令计算。

外部 RAM 只按 Neural CPU 算出的地址读写标记位。它既不知道当前筛到哪个数，也不会替 CPU 判断一个数是否为质数。

  1. Neural CPU 先在 RAM 中筛出不超过 sqrt(180,000,000) = 13,416 的奇数基础质数，而不是由宿主预先提供质数表。
  2. 每条基础质数记录保存 p、32-bit 的 p² 和跨分段延续所需的下一个标记偏移。
  3. 32 KiB 筛缓冲区只表示奇数，因此每段覆盖 65,536 个整数；CPU 清空缓冲区、标记合数并把偏移带到下一段。
  4. CPU 扫描未标记位置，用 24-bit 计数器累计质数名次；达到 10,000,000 时自行组合出 32-bit 结果 179,424,673 并 HALT。

程序由 1,129 条静态机器指令和数据相关循环构成；完整运行执行 4,462,453,580 次神经操作，最终 demo 审计为 0 次执行错误。

神经侧

Neural CPU 承担什么

神经核心 · MLP

以下全部来自 16-bit 指令流的逐条状态转移：

  • 基础质数的生成与记录；
  • p² 与筛缓冲区地址计算；
  • 跨分段的下一个倍数推进；
  • 质数计数与停止条件（数到第 10,000,000 个时停机）。
外部侧

外部运行时承担什么

外部精确组件

  • 16-bit PC 与取指；
  • 64 KiB RAM：只按神经核心算出的地址读写筛标记；
  • batch 模式下生成唯一精确轨迹、做 GPU 调度，并对神经核逐操作审计；
  • 进度打印等宿主侧显示（每 50,000,000 次操作一次）。
验证口径

两种模式

当前脚本支持 exact 与 batch 两种模式，区别在于是谁推进状态、以及是否加载神经权重。

模式含义
exact 不加载神经权重，只运行精确实现，验证筛法程序和机器码（EXECUTION_MODE 设为 "exact" 时生效）。
batch 默认模式。与 pi 相同的轨迹审计：先由精确解释器生成唯一程序轨迹，再把大量相互独立的单步输入组成大 batch 做神经审计。它不是把质数答案从外部直接喂给网络。

两种模式覆盖同一条程序轨迹；模式只改变验证方式，不改变筛法的结果。

运行方法

所有可调参数集中在脚本顶部的 Config。在 neural_cpu_v3/ 目录下运行：

python scripts/run_neural_cpu_v3_primes.py
参数默认值说明
TARGET_RANK10_000_000目标质数名次
EXPECTED_PRIME179_424_673该名次的预期答案
SEARCH_LIMIT180_000_000搜索上界
EXECUTION_MODE"batch""exact" 或 "batch"
MAX_NEURAL_OPERATIONSNone神经操作步数上限；None 表示不设上限
TRACE_BATCH / INFERENCE_BATCH262,144每块轨迹长度 / 单次 GPU 前向规模

快速自检：按脚本开头说明，可把 TARGET_RANK、EXPECTED_PRIME、SEARCH_LIMIT 和 EXECUTION_MODE 分别改为 1000、7919、10000 和 "exact"。

相关文件

  • scripts/run_neural_cpu_v3_primes.py — 脚本（自包含，Config 在顶部）
  • weights/neural_cpu_v3_best_balanced_model.pt — 发布权重（Config.MODEL_PATH 默认值）

输出写入 results/primes/（Config.RESULT_DIR）。

边界

限制与不声称的内容

  • 0 error 是这次最终 demo 审计的结果，不是对任意未来运行的保证；错误率数量级的口径与证据见可靠性页。 可靠性页 →
  • batch 不是把质数答案从外部喂给网络：轨迹由精确实现唯一生成，神经核心逐项接受审计。
  • EXPECTED_PRIME 是脚本内置的预期答案对照；质数本身由筛法指令流计算。
  • 默认目标是数十亿次操作级别的运行，需要 GPU 与相应运行时间；快速自检请用上面的小参数组合。
