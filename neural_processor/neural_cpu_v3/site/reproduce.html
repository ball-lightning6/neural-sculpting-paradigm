准备

环境与依赖

仓库在 CPython 3.13 下开发运行，建议 Python 3.10 或更高版本。全部 8 个脚本都依赖 PyTorch；其余第三方包按脚本列出如下。

每个脚本自动选择 CUDA GPU（torch.cuda.is_available()），没有 CUDA 时退回 CPU。训练、全量验证与图形 demo 的默认规模面向 GPU 设计，CPU 只适合小规模自检。

脚本PyTorch 之外的第三方依赖备注
scripts/train_neural_cpu_v3_hybrid.py—建议 CUDA GPU。
scripts/validate_neural_cpu_v3.py—建议 CUDA GPU。
scripts/run_neural_cpu_v3_pi.pynumpybatch 模式首次运行时用系统 C++ 编译器（g++ 或 clang++）编译原生真值轨迹生成器；该生成器面向 Linux。
scripts/run_neural_cpu_v3_sudoku.pynumpy—
scripts/run_neural_cpu_v3_primes.pynumpy与 pi 相同：batch 模式需要 C++ 编译器，原生生成器面向 Linux。
scripts/run_neural_cpu_v3_mnist_cnn.py—本地缺少 MNIST 测试文件时需要联网下载一次（见下文）。
scripts/render_neural_cpu_fast_clouds_frame.pynumpy, Pillow—
scripts/render_neural_gpu_rubiks_cube_video.pynumpy, OpenCV (cv2)cv2 用于 MP4 编码。

改参数的方式

所有可调参数都在各脚本顶部的 Config

8 个脚本都不使用 argparse，也不读取命令行参数。每个脚本顶部有一个 Config 类，集中保存路径、规模、模式与 batch 等全部可调项；修改参数就是编辑 Config 中的值，然后重新运行脚本。

例如把 pi 的计算位数改为 200：将 scripts/run_neural_cpu_v3_pi.py 中的 TARGET_DECIMAL_DIGITS = 1000 改为 200 再运行即可。下文按脚本列出最常改动的 3 到 6 个参数。

8 个脚本

各脚本：运行命令与常用参数

在仓库根目录执行对应的 python 命令即可。每个脚本自包含，输出写入 results/ 下对应子目录。

训练与全量验证是长时间的 GPU 工作：训练在 RTX 5090 上累计约 2.5 天，全量验证默认 10,737,418,240 次操作；两个图形 demo 的默认运行同样是数十亿 lane-op 量级。正式运行前，先用各脚本的 SMOKE_TEST 或小规模参数做自检。

scripts/train_neural_cpu_v3_hybrid.py

训练神经执行核心：在线生成训练样本，hard replay 与动态审计调度；默认从已发布权重继续训练，按 Ctrl+C 会保存断点。

python scripts/train_neural_cpu_v3_hybrid.py
参数说明
SMOKE_TEST改为 True 执行快速自检。
HARD_REPLAY_MODE从已发布权重继续 hard-replay 训练（默认 True）。
PRETRAINED_MODEL_PATH继续训练使用的起始权重路径。
BATCH_SIZE训练 batch 大小（默认 16,384）。
LEARNING_RATEhard replay 阶段学习率（默认 3e-6）。
MAX_STEPS最大训练步数；None 表示持续训练直到手动中断。

预计成本：RTX 5090 上累计约 2.5 天。

scripts/validate_neural_cpu_v3.py

独立、只读的大规模随机验证器：内嵌网络结构与真值生成器，只加载 checkpoint 做推理，不改写权重。

python scripts/validate_neural_cpu_v3.py
参数说明
SAMPLES随机验证操作总数（默认 10,737,418,240）。
SEED随机种子。
AUTO_TUNE_BATCH启动时实测候选 batch，自动选择吞吐最高的一档。
FALLBACK_BATCH_SIZE关闭自动调优时使用的 batch 大小。
SMOKE_TEST改为 True 执行快速自检。

预计成本：全量验证是长时间的 GPU 工作。

scripts/run_neural_cpu_v3_pi.py

让 Neural CPU 执行 Rabinowitz–Wagon spigot 汇编程序，默认计算 1000 个十进制有效数字。

python scripts/run_neural_cpu_v3_pi.py
参数说明
TARGET_DECIMAL_DIGITS目标十进制位数（默认 1000）。
EXECUTION_MODE"serial" 自主执行或 "batch" 大 batch 审计（默认 "batch"）。
EXACT_ONLY改为 True 只验证汇编程序本身，不加载神经权重。
MAX_NEURAL_OPERATIONS神经操作上限；None 表示不限。
INFERENCE_BATCH单次 GPU 前向规模。

batch 模式首次运行会编译原生 C++ 真值轨迹生成器（面向 Linux，需要 g++ 或 clang++）；1000 位约需数十亿次神经操作。

scripts/run_neural_cpu_v3_sudoku.py

让 Neural CPU 自主执行通用 9x9 Sudoku 求解器，默认从 Project Euler 96 的 50 题中无放回随机抽取 10 题。

python scripts/run_neural_cpu_v3_sudoku.py
参数说明
MODE"exact" / "serial" / "batch"（默认 "batch"）。
PUZZLE直接给定 81 格题目字符串，跳过随机抽题。
PUZZLE_COUNT无放回随机抽题数量（默认 10）。
PUZZLE_INDEXES / RANDOM_SEED固定题号或随机种子，用于复现某次抽题。
MAX_NEURAL_OPERATIONS神经操作上限（默认 1,000,000,000）。

scripts/run_neural_cpu_v3_primes.py

让 Neural CPU 用分段奇数筛寻找第 10,000,000 个质数，默认验收结果为 179,424,673。

python scripts/run_neural_cpu_v3_primes.py
参数说明
TARGET_RANK目标名次（默认 10,000,000）。
EXPECTED_PRIME期望质数，用于验收（默认 179,424,673）。
SEARCH_LIMIT搜索上界（默认 180,000,000）。
EXECUTION_MODE"exact" 或 "batch"（默认 "batch"）。
INFERENCE_BATCH单次 GPU 前向规模。

脚本说明给出的快速自检组合：TARGET_RANK = 1000、EXPECTED_PRIME = 7919、SEARCH_LIMIT = 10000、EXECUTION_MODE = "exact"。batch 模式与 pi 一样需要 C++ 编译器（面向 Linux）。

scripts/run_neural_cpu_v3_mnist_cnn.py

用 Neural CPU 执行量化 MNIST CNN；同时加载 weights/mnist_quantized_cnn_best_model.pt 与 Neural CPU 发布权重。

python scripts/run_neural_cpu_v3_mnist_cnn.py
参数说明
IMAGE_INDEX测试图像序号（默认 0，该图像标签为 7）。
RUN_INTEGER_TEST_SET先在 10,000 张测试图上核对 QAT 与精确整数实现。
RUN_NEURAL是否执行 Neural CPU 前向。
STOP_ON_NEURAL_ERROR遇到首个神经执行错误即停止。
STOP_AFTER_LAYER只执行到指定层（调试用）。
LANE_CHUNK每个 chunk 的 lane 规模。

scripts/render_neural_cpu_fast_clouds_frame.py

用 Neural CPU 渲染 Fast 2D Clouds 的一帧，默认输出 1280x720，并与精确整数参考逐像素对比。

python scripts/render_neural_cpu_fast_clouds_frame.py
参数说明
WIDTH / HEIGHT输出分辨率（默认 1280x720）。
TIME_SECONDSshader 时间常量。

scripts/render_neural_gpu_rubiks_cube_video.py

用 Neural CPU 渲染 3x3 魔方复原视频；默认 pure_flat 模式，640x360，24 fps。

python scripts/render_neural_gpu_rubiks_cube_video.py
参数说明
RENDER_MODE渲染模式（默认 "pure_flat"）。

Notebook 环境

Jupyter / AutoDL 用法

在 Jupyter / AutoDL 中，推荐先把当前工作目录切到 neural_cpu_v3/，再使用 %run scripts/script.py；这与普通 python scripts/script.py 使用同一份文件和路径逻辑，也不会把 Jupyter 自己的 -f kernel.json 参数误交给脚本。8 个发布脚本都不使用 argparse。

8 个脚本在标准 .py 运行时会识别 scripts/ 并把其父目录作为项目根；整段粘贴进 notebook cell、因而没有 __file__ 时，则退回当前工作目录。因此两种方式都能使用，但粘贴运行前必须确认当前目录就是 neural_cpu_v3/。

数据准备

MNIST 数据自动下载

scripts/run_neural_cpu_v3_mnist_cnn.py 默认先在 10,000 张测试图上核对 QAT 与精确整数实现（RUN_INTEGER_TEST_SET = True），再执行 Neural CPU 前向。

如果 assets/mnist_dataset/ 中缺少 MNIST 测试文件，脚本会自动从 Config.MNIST_MIRRORS 配置的镜像下载，并按内置 SHA-256 校验；下载失败时也可以手动把文件放入该目录。

运行模式

serial / batch / exact / REFERENCE_ONLY 的区别

模式行为说明
serial 神经状态沿程序依赖顺序自主逐步前进。 最接近真实单核运行；首次出现差异时可以立即停止（pi、sudoku）。
batch 精确解释器先生成同一条唯一程序轨迹，再把轨迹上大量互相独立的单步输入组成 GPU batch，让神经核心逐项审计。 不改变程序答案，也不是同时计算多个独立程序（pi、sudoku、primes）。
exact / EXACT_ONLY 只运行精确实现，验证汇编程序与算法本身。 不代表神经执行（pi、sudoku、primes）。
REFERENCE_ONLY 图形脚本中的等价开关：只生成精确整数参考画面并核算操作量。 不加载神经权重（clouds、rubiks）。
