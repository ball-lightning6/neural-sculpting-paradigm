口径定义

先定义：三种测量口径

本站所有可靠性数字都对应以下三种口径之一；阅读任何数字前先确认它属于哪一种。

Bit accuracy（逐位准确率）

每次状态转移输出 39 bit。逐位与独立、精确的 ISA 真值比较：任一输出 bit 与真值不符，计 1 个 bit error。这是最细粒度的口径。

Operation exact accuracy（逐操作精确率）

一次操作的全部 39 个输出 bit 都与真值一致，该操作才算 exact；只要 1 个 bit 出错，整个样本计为 1 个 sample exact error。这是单步操作的最严格口径。

Program trajectory audit（程序轨迹审计）

在真实程序产生的长指令轨迹上逐步比对神经核心与精确 ISA 实现。serial 模式让神经状态自主前进、首次差异即停；batch 模式把同一条唯一精确轨迹上的独立单步组成大批次审计，不改变程序答案。

历史测试

相邻 checkpoint 的历史大样本测试

训练过程中，相邻阶段的最佳 checkpoint 还做过两次独立大样本测试；连同最终发布权重的验证，事件计数如下。

  1. 10,737,418,240 次操作 · 0 error

    相邻训练阶段的一个最佳 checkpoint。

  2. 32,212,254,720 次操作 · 3 errors

    另一个相邻最佳 checkpoint；3 个错误分别出现在 XOR、CMP、ADDI。

  3. 10,737,418,240 次操作 · 1 error

    最终发布权重（checkpoint step 6,926,625）；错误来自 JG，细节见上方最终随机验证与下方错误案例。

这三次测试使用的是训练过程中相近但不完全相同的最佳 checkpoint，不能简单合并成一个精确频率估计。谨慎的表述是：随机单步操作错误率处于每约 10^10 次操作一个错误的数量级。

谨慎措辞

为什么不能声称“100 亿次必不出错”

  • “每约 10^10 次操作一个错误”是由有限的罕见事件计数得到的数量级估计：几次大样本测试合计只观察到 0、1、3 个错误。
  • 相邻 checkpoint 的结果来自相近但不完全相同的权重，不能合并成精确的错误频率。
  • 这是一个训练得到的神经网络权重的实测错误率，不是硬件级可靠性，也不能与真实硅 CPU 的可靠性相比较。

该数量级估计来自有限罕见事件，不是硬件级可靠性保证，也不能写成“严格保证 100 亿次不出错”。

分布覆盖

为什么真实程序分布和全局随机分布都要测

全局随机验证中，35 个状态 bit 约有一半为 1；真实程序轨迹却经常经过全零、近全零、常量初始化、刚清空的寄存器等结构化状态。

实际运行 pi 程序时，早期模型在零很多的状态上暴露出远高于全局随机验证的错误率；对称地，接近全 1 的状态也可能构成另一类边界。

因此训练加入了 SPARSE_STATE 与 DENSE_STATE 两个结构组；验证侧也必须同时覆盖全局随机分布与真实程序轨迹——六个 demo 的逐轨迹审计属于后者。
